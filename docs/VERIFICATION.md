# Local Verification / 本地验证

Recorded on 2026-11-01. These are local checks, not a claim that remote CI or a new in-game test has taken place.

## Build and Regression

- Windows x64, Visual Studio 2022 ClangCL, Clang 19.1.5, Windows SDK 10.0.26100.0.
- Debug and Release compile with the static C++ runtime and static zlib-ng.
- Both configurations pass all five CTest suites: `core.config`, `core.codecs`, `core.builder`, `core.deployment`, `cli.workflow`.
- Fixtures cover French, Japanese, Korean and missing-language handling. Rendering tests temporarily copy a local Windows font; font binaries are never committed.
- Serial/parallel generation produces identical bytes. Same-font/same-size raw-glyph reuse is compared against non-shared rendering with distinct role-specific alpha/outline settings. Optional warm glyph-cache output is identical as well.
- Tests cover DAT role mapping, fmap/UV validity, top safety padding, fixed TEX slots, non-font image isolation, cache invalidation, source changes, concurrent destination locking, failed-build retention and deploy/restore rollback.
- BAT tests use a different current directory and paths containing spaces and `!`, and verify that errors remain nonzero after the pause wrapper.

## Private Resource Regression

A local, ignored copy of existing development inputs was used for an offline full build. None of these inputs is in the repository or tool ZIP:

- 56 JSON files, selected language `zh_CN`, 1448 display codepoints including basic ASCII.
- The existing 31px/30px TTF-first configuration, no outline, its fallback and ASCII font layers, and an explicit capacity TEX template.
- Complete build: about five seconds on this machine, not a performance guarantee on other hardware.
- All 56 GXT files match the legacy generator's current output by SHA-256.
- Font resources also match byte for byte:

| Resource | SHA-256 |
| --- | --- |
| `global/initscripts/font.dat` | `f2c13e3f17ab0458200655a23a193d2f6b909319e7455fb4702911b87c225dec` |
| `global/pictures/global_pc.tex` | `c9a26e1a6322e697910f77bfc47ef29c163447014749334a23a6786e563f266b` |

Offline mixed Chinese/Latin/digit BMP previews were inspected for both roles. A character absent from the selected input corpus appears as missing in the raw preview, not as a silently substituted system glyph.

## Release Boundary

The ZIP contains the EXE, five BAT files, configuration, empty input directories, documentation and licenses only. It excludes private JSON, fonts, original/generated game resources, capacity TEX templates, ASI plugins and loader DLLs. Executable imports use Windows system DLLs, not an external VC runtime or zlib DLL.

No installed game resources, saves, VM state or legacy workspace files were modified. Offline hash regression preserves the previously generated bytes, but does not replace final in-game acceptance. Large glyph sets still require a user-supplied compatible TEX with sufficient fixed-slot capacity.

## 中文摘要

Debug、Release 各通过 5 组测试，包括字体角色映射、顶部留白、并行一致性、同字体复用、缓存、BAT 路径和部署回滚。用现有资源副本构建的 56 个 GXT 及 DAT/TEX，均与旧生成器当前产物的 SHA-256 一致。两套字体已做离线混排预览。

真实译文、字体、原版资源和容量模板只在忽略的 build 目录内，不随源码或工具包发布。这次没有部署或启动游戏，没有更改旧工作区，也没有执行远端 CI。哈希一致不代表可以跳过最终游戏验收；大字库仍需要使用者提供容量足够、布局兼容的 TEX 模板。
